# AttestKit 0.2.0 Release Candidate

## Summary

This release adds deterministic comparison of two integrity-checked execution receipts. It answers what changed between two recorded runs without rerunning either command or uploading workspace content.

## Included

| Area          | Evidence                                                                                                                   |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Core          | `compareReceipts` with `attestkit-comparison/v1` report output                                                             |
| CLI           | `attestkit compare baseline.json current.json` with text, JSON, and Markdown formats                                       |
| Safety        | Both receipts are structurally validated and digest-verified before comparison; no artifact paths are read                 |
| Diff detail   | Status, command argv, source context, warnings, and artifact added/removed/changed/unchanged paths                         |
| Documentation | README, CLI reference, ADRs, and explicit verification boundary                                                            |
| Tests         | Identical pair, changed status/source/command/artifacts, tampered receipt rejection, full quality gate, and CLI smoke test |

## Non-goals

The report does not prove semantic correctness, security, authorship, reproducibility, or equivalence of two software runs. It does not parse JUnit/SARIF internals, execute commands, inspect source files, or decide whether a difference is acceptable.

The existing `attestkit/v1` receipt protocol remains unchanged. Consumers that do not use comparison can continue to verify existing receipts without migration.
